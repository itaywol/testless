> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Function-level `Calls`/`Reads` edges in the graph across all three languages, with tier-1 (name + import-scope) resolution and `Unknown` widening markers — the substrate Plans 3-4 (diff + walk) select against.

**Architecture:** First a type-safety refactor (DefId/FileId newtypes, typed Edge enum — mandated by Plan 1 final review before adding a third edge kind). **Tech Stack:** existing workspace; no new dependencies.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize)]
pub struct DefId(pub u32);
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize)]
pub struct FileId(pub u32);

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub enum Edge {
    Contains { parent: DefId, child: DefId },
    Imports { from: FileId, to: FileId },
    Calls { from: DefId, to: CallTarget },
    Reads { from: DefId, to: DefId },
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub enum CallTarget {
    Resolved(DefId),
    Unknown(String), // name recorded for walk-time widening
}

pub struct Graph {
    pub files: Vec<FileNode>,
    pub defs: Vec<Def>,          // Def.file: FileId (newtype)
    pub edges: Vec<Edge>,
}
impl Graph {
    pub fn add_file(&mut self, f: FileNode) -> FileId;
    pub fn add_def(&mut self, d: Def) -> DefId;
    pub fn add_edge(&mut self, e: Edge);
    pub fn def(&self, id: DefId) -> &Def;             // defs[id.0 as usize]
    pub fn defs_in_file(&self, f: FileId) -> impl Iterator<Item = (DefId, &Def)>;
    pub fn module_init(&self, f: FileId) -> Option<DefId>;
}
```

### Task 3: lang-ts call/read extraction

**Files:**
- Modify: `crates/lang-ts/src/lib.rs`; Create: `crates/lang-ts/tests/refs.rs`

**Behavior:**
- Track enclosing-def index during the walk (fn/method/arrow bodies; top-level → module_init index 0).
- `call_expression`: callee `identifier` → call `{name}`; callee `member_expression` `obj.method` → call `{name: method, qualifier: obj_text}`. `new X()` (`new_expression`) → call `{name: X}` (constructor ≈ class).
- Reads: `identifier` nodes that are NOT the callee of a call, NOT a def name, NOT a property key — restricted to identifiers matching names imported in this file OR defined at this file's top level (cheap filter — avoids flooding with locals). Qualified member reads (`ns.CONST`) → read `{name: CONST, qualifier: ns}`.
- Test-body references: calls inside `it`/`describe` callbacks attribute to the TestCase def (the enclosing-def tracking must treat TestCase defs as enclosing scopes).

### Task 4: lang-go call/read extraction + `.Run` receiver narrowing

**Files:**
- Modify: `crates/lang-go/src/lib.rs`; Create: `crates/lang-go/tests/refs.rs`

**Behavior:**
- `call_expression`: function `identifier` → `{name}`; `selector_expression` `pkg.Fn` / `recv.Method` → `{name: Fn/Method, qualifier: pkg_or_recv_text}`.
- Reads: selector/identifier references to package-level symbols — same cheap filter idea (imported package qualifiers or same-file top-level names).
- Attribution: enclosing function/method/TestCase def; top-level (var initializers) → module_init.
- **Carry-forward fix:** subtest detection (`t.Run`) currently fires on ANY `x.Run(...)`. Narrow: receiver identifier must equal the enclosing test fn's `*testing.T`/`*testing.B` param name (track it when creating the TestCase root; `t.Run` inside a subtest closure: the closure's own param name). Non-matching `.Run` calls become ordinary call refs `{name: Run, qualifier: recv}`.

### Task 5: lang-rust call/read extraction

**Files:**
- Modify: `crates/lang-rust/src/lib.rs`; Create: `crates/lang-rust/tests/refs.rs`

**Behavior:**
- `call_expression` with function `identifier` → `{name}`; function `scoped_identifier` (`math::add`, `crate::math::add`) → `{name: last_seg, qualifier: prefix_text}`; function `field_expression` (rare fn-field) → `{name: field, qualifier: obj}`.
- Method calls: in tree-sitter-rust these are `call_expression` whose function is a `field_expression`? No — method calls are their own shape: `call_expression(function: field_expression)` covers `x.f()` — treat as `{name: f, qualifier: x}`.
- Macro invocations (`format!`, `assert_eq!`): skip (stdlib noise); EXCEPT record nothing — macros that call user code widen via Unknown anyway? They don't produce refs at all — document this limitation in a comment (structural diff still catches same-file changes via containment; cross-file macro calls are a known tier-1 gap, spec's over-approx via module_init import edges covers module-level impact).
- Reads: `identifier`/`scoped_identifier` refs filtered to imported names or same-file top-level names (same cheap filter).
- Attribution: enclosing fn/method/TestCase; top-level → module_init.

### Task 6: Core tier-1 resolver

**Files:**
- Modify: `crates/core/src/indexer.rs`; Modify: `crates/cli/tests/index.rs` (integration tests — all langs linked)

**Behavior (new pass 3, after imports):** for each file F, def D, ref R (calls and reads):

1. Candidate defs named `R.name`: (a) in F itself; (b) in every file F `Imports`; (c) qualified methods: if `R.qualifier` present, also match defs named `*.{R.name}` (e.g. `Calc.push`, `calc.Add`→`Add`) in those scopes.
2. ≥1 candidates → edge to EVERY candidate (`Calls{from, to: Resolved(id)}` per candidate / `Reads`). Over-approx by design.
3. 0 candidates AND ref is a call → `Calls{from, to: Unknown(name)}`. 0 candidates for reads → drop (reads of locals/stdlib — module_init import edges already cover file-level impact).
4. `from` def: map `R.from_def` extraction index → DefId via the per-file base offset (existing mechanism).

Dedup: `HashSet` over `(from, to)` pairs like imports.
